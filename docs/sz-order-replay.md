# 深市订单回放

## 限价单：只由逐笔生命周期维护

`OrdType='2'`（raw 数值 50）统一使用 `Provided(source_price) + Rest`。
新增按源价格登记全部数量，成交扣减引用订单，撤单移除真实余量；穿价不触发
隐藏、撮合、删除或重定价。逐事件中间状态允许交叉，不能将其自动视为交易所
曾发布的稳定十档。复牌集合竞价未成交的限价单无需等待自身成交才能重新显示。

旧 `H0 → T0` 同时间戳复牌特判已移除，恢复不读取 raw snapshot；`H0/V0` 等状态
仍由验证器用于选帧与诊断，不反向决定限价单可见性。固定 `< T` 截面和验证窗口不变。
本变更不修改核心/legacy/沪市规则，也不重写下述市价与本方最优策略；后两者读取
盘口进行定价/入簿判断的交互必须回归，不能用单个 V0 样本通过代替全市场正确性证明。

## 目标与证据边界

生产恢复不重新撮合，不由 snapshot 价量补簿。当前 CLI 默认使用实用策略
`RestAtLastTradePrice` 恢复深市市价单；它不等于完整的市价语义，也不保证每个中间态
正确。官方规则区分对手方最优、本方最优、五档 IOC、IOC、FOK，
见[深交所交易规则第 3.3.4、3.3.6、3.3.21 条](https://docs.static.szse.cn/www/lawrules/rule/trade/current/W020260424690713155663.pdf)。

本轮只读核对了 `20260828/mdl_6_33_0/part-0.parquet` 的 Arrow schema 和 Clara footer：

- 源列包含 `ChannelNo/ApplSeqNum/MDStreamID/SecurityID/SecurityIDSource/Price/OrderQty/Side/
  TransactTime/OrdType/LocalTime/SeqNo`；Clara 另加 `source_row_no`。
- 不包含 `TimeInForce/MaxPriceLevels/MinQty` 或即时执行结束标识。
- footer 的 schema 为 `tonglian.level2.v4_1.SZ.mdl_6_33_0`，来源为
  `20260828_mdl_6_33_0.csv.7z` 内同名 CSV；源表头哈希为
  `f62740cb2837ea89ce07c0ba1412a1890cb915b08990d935f9518b49c7d089c1`。

这证明本文件缺少上述字段，不证明自动撤单保证邻接，也不证明其他日期的模式一致。
未确认消息组结束契约前，严格模式拒绝推断有余量的市价单。当前默认实用策略不等待
此契约；股票和 ETF 采用相同策略，并通过独立 snapshot 对拍评估结果。

## 当前默认策略：先恢复，再做全量对拍

CLI 深市请求默认 `--sz-market-order-policy rest-at-last-trade-price`：

- `OrdType='1'` 使用 `Unpriced + RestAtLastTradePrice`，先隐藏，不以保护价入簿。
- 隐藏订单发生部分成交时，价格更新为该订单参与的这笔成交价；成交后不再穿越对手盘
  （或对手盘为空）才把余量入簿。仍穿越时继续隐藏。
- 入簿后价格固定，成交只扣量，撤单只删除真实剩余量；不自行撮合或生成重复撤单。
- 逐条应用、逐事件提供验证候选，不进入严格待决组，不要求响应同毫秒或序号相邻。
- 本方最优仍按接收时本方最优价固定定价；空本方盘口仍执行下文的严格撤单对账。

已知限制：IOC 等订单可能在成交与自动撤单之间产生临时可见余量。周期快照匹配并不
证明每个逐事件状态或 FIFO 路径正确，也不证明此类临时状态不会影响后续本方最优订单。
精确即时响应结束及避免临时挂单留待未来升级，不以放宽快照窗口掩盖问题。

显式选择 `require-evidence` 可恢复严格待决解析；`assume-contiguous` 保留为诊断策略。
旧 `--assume-sz-contiguous-responses` 与新策略参数互斥。沪市不接受显式深市策略参数。
Rust 调用者通过 `MarketDayRequest.sz_market_order_policy` 选择策略；枚举的 `Default`
保留 `RequireEvidence`，避免历史缺失字段的报告被误解释为新实用策略。

报告 `sz_market_order_policy=rest_at_last_trade_price` 明确标记算法，`is_success()` 仍检查
快照差异、数据错误和来源完整性。实用策略的 `is_standard_acceptance()` 保持 false，
不能当作严格待决模式验收。`sz_pending_groups` 只统计实际进入待决解析的订单，默认
市价单不计入该值；空簿本方最优仍可能计入。

## 保留的严格／诊断待决处理路径

```text
原生 ApplSeqNum 双流归并
→ PendingOrder：缓冲、校验关联响应及数量
→ Terminal / Rest(price) / UnresolvedSzOrder
→ 原始 AddOrder、Trade、OrderCancel 顺序应用
→ 必要时显式完成余量入簿
→ 仅发布已确认处理组的最终状态
```

双流归并前，各流按通道检测自然有序段；遇到偶发逆序仅修复异常临时分片，再进入
上述路径。不按证券拆分顺序域，也不改变待决响应的通道相邻性。
详见[深市偶发逆序处理](full-market-replay-guide.md#深市偶发逆序处理)。

`MarketDayRequest.sz_market_order_policy` 有三种值：

| 策略 | 用途 |
| --- | --- |
| `RestAtLastTradePrice`（深市 CLI 默认） | 逐笔成交后按不穿越条件入簿；不提供精确路径保证 |
| `RequireEvidence`（Rust 枚举默认，CLI 显式） | 全成／全撤可闭合；有余量且无明确执行限定或结束证据时失败 |
| `AssumeContiguous` | 诊断实验：显式假设即时响应连续发布，满足额外校验后允许推断余量 |

CLI 通过策略参数或兼容开关选择 `AssumeContiguous`。它不是已核验的数据源契约，
即使 snapshot 全匹配，`is_standard_acceptance()` 仍为 false。SH 请求应拒绝该参数。
报告记录策略、`sz_pending_resolution_version=1`、待决组数、推断余量数和空簿本方最优
撤单对账数；旧报告反序列化版本为 0，不能自动成为当前算法的标准验收证据。

## 严格／诊断模式的市价订单

接收 `OrdType='1'` 时保存原始价格、数量和接收前对手方最优价。原始价格不直接用于
入簿，不因 `Price=0` 生成虚构价格。读入后续关联成交／撤单，但暂不修改公开盘口。

保留的待决实现要求（不适用于默认实用策略的市价单）：

1. 关联使用证券、通道、方向及订单编号，不仅比较某一侧数字。
2. 响应按原生序号严格相邻，不能跨越其他记录或过滤导致的序号缺口。
3. 全组 `quote_time` 相同；这是一项明确的实现限制，不是声称行情协议必然如此。
   跨毫秒直接失败，避免把未来结果倒填到严格 `< T` 截面。
4. 每组最多 65,536 条响应，超出报错；不无限等待，不无界缓存。
5. 成交数量必须为正且不超余量，撤单必须单侧引用且数量恰好等于剩余量。

| 观察结果 | 严格模式处理 |
| --- | --- |
| 累计全部成交 | 删除订单，不进入可见档位 |
| 无成交／部分成交后完整撤单 | 删除剩余量，不产生临时可见挂单 |
| 仍有余量，响应序列停止 | `UnresolvedSzOrder`，不能仅凭单一成交价认定为对手方最优 |
| 同一订单响应跨毫秒、跨原生序号缺口 | 明确失败，不宣称原始数据必然错误 |

诊断模式也不会盲目入簿：必须有成交、全部同价、成交价等于接收前的对手方最优价，
且存在紧接的下一条原生记录；EOF 或序号缺口不作处理结束证据。多价成交仍有余量、
没有成交、价格证据不一致均失败。入簿前核心再次检查余量价不穿越对手盘及聚合量溢出。

完整成交／撤销只能确定组结束时的状态，不一定能识别原始委托属于 IOC、FOK 还是
对手方最优。程序不伪造子类型，也不把未来较晚的主动撤单归并为即时撤单。

## 本方最优订单

- 本方存在有效盘口：接收时一次性取本方最优价，按原生顺序入 FIFO，不随最优价变化，
  不使用委托的原始参考价格。
- 本方为空：不作为无限期隐藏活动单存续。当前实现要求同毫秒相邻的源全量撤单完成
  对账；缺失／跨时间／数量不符均失败，意为当前契约不足，不推断交易所未自动撤销。
- 处理组成功应用时，内部临时订单及源撤单均参与序号／时间审计，但不向查询或验证器
  暴露中间隐藏状态；也不再额外生成第二笔合成撤单。
- 严格／诊断模式的前序待决组未完成时，不处理依赖该盘口的后续委托。实用市价策略
  不采用此屏障，前文所述临时可见余量影响后续 `U` 定价的风险仍然存在。

## 待决组的原子性、时间及验证

分类及响应数量校验先于组内订单簿修改；组内原始事件依次使用核心现有的失败原子性。
组执行期间不通知外部观察器，也不写组中间截面。若某次核心应用失败，整个通道立即
终止，其私有 runtime 不返回；已写出的较早截面只能作为失败运行的部分输出，不能算
成功结果。没有复制全量订单簿，也不承诺可从半组失败原地恢复。

组内原始事件保持自己的 raw/apply sequence 和 local/quote 元数据。显式余量入簿不是
新原始事件，不增加合成序号，不使用下一条消息的时间。下一条委托在完成余量入簿之后
才应用，因此不以解析延迟改变 FIFO。成交额和收盘 VWAP 仍来自实际逐笔成交。

同一行情毫秒的组先输出 `T <= quote_time` 的到期左极限截面，成功后发布组最终状态。
验证器不再将这些待决组的猜测中间状态作为匹配候选；因此旧算法候选集合及全量报告
不能直接沿用。普通限价、SH 和 legacy C++ 路径不启用待决市价策略。

该阶段实现了上述严格拒绝和诊断推断路径、结构化错误、版本审计、空簿本方最优对账，以及
