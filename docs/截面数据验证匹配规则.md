# 恢复实时订单簿与截面数据验证匹配规则

本文是 snapshot 与逐笔恢复订单簿匹配规则的唯一规范来源，只定义验收必须满足的行为，
不记录具体版本的实现进度。

实现限制必须明确报告，不能静默放宽规则。命令见[使用手册](使用手册.md)，
算法与限制见[实现说明](订单簿恢复实现说明.md)。具体版本与验收证据仅在本地 `reports/`
留存，不随仓库提供；历史报告不因规范更新自动成为新规则的验收结果。

## 规则速查

参考源为 raw snapshot；`T` 为参考帧时间，所有候选窗口均左闭右开。

| 验证阶段 | 沪市股票、ETF | 深市股票、ETF |
| --- | --- | --- |
| 开盘集合竞价结束 | 正常 `OCALL → 首个 TRADE`，位于 `[09:25,09:30)`；窗口 `[T,T+1s)` | 正常 `O0 → 首个 B0`，尚未进入 `T0`；窗口 `[T,T+1s)` |
| 盘中交易 | 09:30 起的正常 `TRADE`，保留 `14:57:00 TRADE`；窗口 `[T-1s,T+1s)` | 正常 `T0`；主板 `[T,T+1s)`，ETF `[T,T+1.1s)`，创业板 `[T,T+3s)` |
| 收盘阶段结束 | 股票及 `20260706` 起的 ETF：首个正常 `CCALL → CLOSE`；此前 ETF：首个正常 `TRADE → CLOSE`。均对比逐笔流首个有效 `CLOSE` 检查点状态 | 完整回放当日委托、成交／撤单，对比正常 `C0 → 首条 E0`；不按 `quote_time <=15:00` 截断 |

- 三个阶段使用统一完整字段集合；候选必须在同一状态同时满足所有字段。
- 停牌按阶段排除，复牌后正常阶段继续验证；`CCALL/C0` 不参与普通盘中盘口比较。
- PreOpen、MarketClose 只比较首条有效参考帧，后续静态帧不解析盘口、不检查字段一致性。
- 深市出现 `quote_time >15:00:00.000` 时须报告并确认业务阶段，不能直接把独立盘后
  交易后的状态当作 E0 状态。收盘不使用候选窗口。
- 验证不改变原生序号回放，也不改变生产截面的严格 `quote_time < T` 语义。

## 1. 适用范围与数据来源

适用于完整单日 Parquet 的离线回放：一个交易日、一个市场，可选择股票、ETF 或二者。
股票和 ETF 共用流程、比较字段和异常分类；市场、板块和品类差异由明确的参数与规则表达。

参考源必须是独立 raw snapshot，不使用 canonical snapshot，也不读取 `.csv.7z` 执行生产
验证。数据集及目录布局统一见[输入说明](使用手册.md#输入与证券范围)。

## 2. 阶段选帧与收盘边界

### 2.1 开盘集合竞价结束

- 沪市：选择正常 `OCALL → TRADE` 转换后、`[09:25,09:30)` 内首条 `TRADE`。
- 深市：选择正常 `O0 → 首个 B0`，且此前尚未进入 `T0`。
- 两市均在 `[T,T+1s)` 内寻找候选状态。参考帧是整秒阶段时间，不能仅按同毫秒比较。
- 正常转换不得跨越停牌等异常阶段；“当天曾出现过 OCALL/O0”不足以证明正常转换。
- 深市只选正常开盘阶段的第一条 B0；后续开盘 B0 和午间 B0 不产生比较任务。
- 缺少正常开盘前驱、时间不符合条件时不选帧，只汇总原因；不影响之后有效参考帧。

### 2.2 盘中交易

- 沪市：09:30 起的正常 `TRADE`，使用 `[T-1s,T+1s)`。保留 `14:57:00 TRADE`，
  不用 `<14:57:00` 硬截断参考帧。
- 深市：正常 `T0`，主板股票使用 `[T,T+1s)`，ETF 使用 `[T,T+1.1s)`，创业板股票使用 `[T,T+3s)`。
- ETF 的 1.1 秒窗口仅用于盘中验证，右端不包含 `T+1100ms` 的事件；PreOpen 仍为
  `[T,T+1s)`，E0 仍按完整收盘状态精确比较。混合请求逐证券选取窗口，不能将整个深市
  请求统一扩为 1.1 秒；显式窗口覆盖继续标记为诊断模式。
- `CCALL/C0` 仅标记收盘集合竞价阶段，不比较普通盘中盘口。
- 临时停牌后恢复正常交易的 `TRADE/T0` 重新纳入比较。不满足阶段条件的记录只进入选帧审计，不能
  仅凭状态文字任意挑选参考帧。
- 时间窗口属于当前数据源验证契约，不是交易所通用时间规则；不得失败后自动扩窗。

### 2.3 收盘阶段结束（集合竞价或历史 ETF 连续竞价）

沪市：

1. 按请求的交易日与证券类型选择首条正常 `CLOSE`：

   - 股票：始终要求正常 `CCALL → CLOSE`。
   - ETF：`trading_day >= 20260706`（含生效当天）要求正常 `CCALL → CLOSE`；
     `trading_day < 20260706` 要求正常连续交易 `TRADE → CLOSE`。
   - 前驱转换不能跨越 `SUSP` 等异常状态；历史 ETF 仅有开盘前的 `TRADE` 不足以
     选中收盘帧。临停后恢复正常连续交易的 ETF 可按正常转换参与收盘验证。

2. 恢复器在对应通道按 `BizIndex` 处理到该证券首个有效逐笔 `CLOSE` 状态事件。
   原始标识为 `Type=S` 且 `TickBSFlag=CLOSE`；之前的有效委托、撤单、成交全部应用。
3. 状态事件本身不修改盘口。检查点由原生序列位置确定，不使用 snapshot 的时间戳或
   接收时间截断逐笔，也不按 `quote_time <=15:00` 判断。
4. 沪市逐笔 `S` 不推进业务时间检查、普通候选窗口或定时截面；`CCALL` 不证明较早
   `TickTime` 的业务事件已全部到齐。只有委托、撤单、成交触发普通候选比较，完整输入
   结束时补齐待验证的继承状态。候选窗口宽度和比较字段不因此改变。
5. `CLOSE` 回调仍在原生检查点立即执行。写 Parquet 时保留该处捕获的收盘截面，待
   通道耗尽、普通截面写完后再写出；不以 EOF 重新计算收盘状态。重复逐笔 `CLOSE`
   不重复捕获，首次 `CLOSE` 后若仍有业务事件则报错，不能静默改写收盘状态。

该日期分界依据[上交所 2026 年交易规则修订说明](https://star.sse.com.cn/aboutus/mediacenter/hotandd/c/c_20260424_10816474.shtml)：
基金自 2026-07-06 起由收盘连续竞价改为收盘集合竞价。历史 ETF 的正常 `TRADE`
仍按盘中规则验证至实际收盘状态，不以 14:57 硬截断。日期分支只决定首条有效 CLOSE 的前驱条件，
不将单独的 `ClosePrice` 替代订单簿最新成交价 `LastPrice`。

深市：

1. 参考源只选正常、未被中断的 `C0 → 首条 E0`。`T0 → E0` 缺少 C0，跳过比较并汇总
   原因，不报阶段错误。未选中的 E0 不阻止后续有效 C0→E0；选中后不再解析重复 E0 盘口。
2. 完整读取当日委托和成交／撤单文件，按通道内 `ApplSeqNum` 合并回放；全部有效事件
   成功应用后，以最终盘口进行静态比较，不使用 `quote_time <=15:00:00.000` 筛掉输入。
3. 单独统计 `quote_time >15:00:00.000` 的记录。若出现，须确认业务阶段；未确认前
   不得宣告最终状态就是 E0 状态，更不能混入独立盘后交易后仍报告收盘验收通过。

共同约束：

- 收盘不使用候选窗口，也不要求收盘集合竞价实际有成交。
- 已选第一帧字段非法或不匹配仍失败，不能跳过后改选恰好匹配的一帧。
- 深市 E0 位于独立 snapshot 流，不是逐笔 `ApplSeqNum` 中的状态事件。离线文件读完
  与输入完整性是上述规则的前提；未来实时接入必须另有“逐笔已收齐”机制，不能收到
  E0 就宣告回放完成。

## 3. 候选状态匹配语义

开盘及盘中阶段统一采用以下规则：

1. 始终按市场原生序号回放，不按行情时间、接收时间或 snapshot 序号重排逐笔。
2. 检查规定窗口内成功应用事件形成的状态；窗口内无事件时，持续存在的盘口也可作为
   候选。窗口右端点上的事件不进入该窗口候选。
3. 存在一个候选状态，其全部规定字段同时满足比较要求，即判定参考帧匹配。
4. 不允许十档、总量和成交统计分别命中不同候选后拼接为匹配。
5. 失败事件不得改变订单簿或形成成功候选，回放错误必须独立报告。

记录命中候选时间及对应原生序号。时间对外使用毫秒精度；内部纳秒容器不代表源数据
具有纳秒测量精度。静态延续状态的候选时间与最后成功事件时间不是同一概念。

验证窗口与生产截面相互独立：

```text
Snapshot(T) = 按原生序号成功应用所有 quote_time < T 事件后的订单簿状态
```

## 4. 比较字段与数值口径

三个阶段使用同一组字段：

| 类别 | 比较内容 | 要求 |
| --- | --- | --- |
| 十档盘口 | 买卖十档价格、数量、每档委托数 | 规范化后精确一致 |
| 全簿汇总 | 买卖总委托量 | 精确一致 |
| 加权价格 | 买卖加权平均价格 | 按规定发布精度处理后，绝对误差 `<=0.001 元` |
| 成交价格 | 最新价、最高价、最低价 | 精确一致；深市收盘 LastPrice 按第 5 节处理 |
| 成交累计 | 成交笔数、成交量、成交额 | 统一整数单位后精确一致 |

- 内部价格乘数固定为 `10_000`，即一个单位为 `0.0001 元`；这不等于证券最小报价单位。
  成交额使用足够宽的整数类型，运算须检查溢出。
- Decimal 直接十进制转换，不经 Float64。确需兼容 Float64 时，使用已验证的舍入
  归一化方法，不恢复会误拒的旧误差阈值；不得通过降低精度掩盖真实差异。
- 零价或 null 价可规范为空档，但数量、委托数必须符合空档约束；非法组合报错，
  不能直接清零。
- 时间戳、接收时间、序号、状态、昨收和开盘价不作为普通盘口一致性字段。
  状态用于选帧，前收盘价可用于深市当日无成交的收盘价处理。

### 接收信息双空的已知数值兼容

仅当同一条 raw snapshot 的 `SeqNo` 为 null，且 `LocalTime` 为 null 或空字符串
（去除首尾空白后为空）时，允许以下两种兼容。`SeqNo=0` 不等于空；缺列、类型错误
仍是 Schema 错误。双空只是兼容条件，不等于已证明该帧来自回补。

- 成交额：先按 `10_000` 转为整数。仅当恢复成交额按 **12 位有效数字、四舍五入**
  后与参考整数完全一致，才消除此字段的差异；不使用任意 epsilon，不修改恢复值。
  适用于三个比较阶段，其他字段仍按原规则比较。
- 深市 HighLimit：仅将 `HighLimitPrice=1000000000.0000` 且
  `LowLimitPrice=0.0100` 这一已知组合中的上限归一化为 `999999999.9999`。
  双空必须出现在携带异常上限的那条记录上，不借用其他帧的接收字段。
  日级属性一致性检查继续执行，其他上限、下限或日内冲突不获豁免。

兼容匹配仍计入 `Matched`，不跳过整帧。报告通过 `match_tags` 统计
`MISSING_RECEPTION_TURNOVER_12_DIGITS` 和 `MISSING_RECEPTION_SZ_UPPER_LIMIT_SENTINEL`；
保留成功明细时，`turnover_precision` 记录真实/参考成交额整数和舍入单位，
`close_price_band.upper_limit_normalization` 记录上限归一化数量、首个来源及前后整数。
多个兼容标签可属于同一成功帧，因此标签计数之和不等于匹配帧数。

## 5. 深市收盘比较规则

### 5.1 LastPrice

股票和 ETF 共用以下决策流程，保留适用品类的价格取整单位差异：

| 情况 | 处理 |
| --- | --- |
| LastPrice 已一致 | 正常比较 |
| LastPrice 不一致，收盘集合竞价有成交 | 判定不匹配，不启用回退 |
| LastPrice 不一致，收盘集合竞价无成交，当日有成交 | 独立计算最后一笔成交前 60 秒至该笔成交（含端点）的 VWAP，按适用价格单位取整 |
| 当日无成交 | 使用前收盘价作为比较用收盘价 |

只有独立计算结果与参考 LastPrice 一致，且其他比较字段全部满足要求，才判定匹配并
记录规则标签。前收盘价等必要输入缺失时不能虚构数值。

该处理不修改订单簿内部最后成交价，不豁免股票或 ETF 的价格比较。沪市保留自身
LastPrice／ClosePrice 字段语义，不机械套用深市转换。

### 5.2 无涨跌幅限制股票的 E0 价格范围投影

仅深市股票、当日明确无涨跌幅限制、正常 E0 收盘比较同时成立时启用。
规则在比较前确定，不以原始盘口是否匹配作为启用条件，不按证券名单特判。

- 验证器从日级证券属性确定是否无涨跌幅限制；当前通联 adapter 从 raw snapshot 的
  `HighLimitPrice/LowLimitPrice` 提取并检查所选证券全天一致性。无上限哨兵为
  `999999999.9999`，当前股票下限接受 `0.01` 或官方无下限负哨兵。未知、空值、非法值、
  类型/scale 错误或日内冲突不能默认通过，相应 E0 报 DataError。
- 基准为按原生序号成功应用的 `quote_time <14:57:00` 最后一笔实际成交；记录该笔时间
  和原生序号。最终成交、VWAP、参考 E0.LastPrice 不覆盖基准；基准缺失报 DataError，
  不借用 5.1 的前收盘价回退。14:57 仅用于基准选择，不截断当日回放。
- 基准乘 90%/110%，按股票最小申报单位四舍五入；按交易规则处理距基准不足一档和
  最低有效价格边界。内部使用 scale=10_000 整数和溢出检查，区间包含上下端点。
- 只对 Rust 的完整价位集合做只读投影，再取十档；总量和加权价使用范围内全部价位，
  不能先截十档再筛选。成交统计保持完整，LastPrice 独立沿用 5.1。
- raw E0 不过滤、不修改；其范围外档位仍会导致不匹配。已选参考的其他
  字段、容差、失败标准保持不变，不尝试多个范围直到匹配。
- 完整订单、余量、FIFO、事件元数据、replay 和生产截面输出不变。范围外不展示仅指
  validation 临时比较视图，不意味着删除或撤销源订单。
- 详细 ValidationRecord 的 `close_price_band` 记录规则、基准、上下限、范围外买卖数量
  和日级属性来源；成功与失败的投影均记录，不替代匹配结果。需要保留成功记录时使用
  `--retain-matched-records`。不适用于 ETF、沪市、普通限价股票或非收盘阶段。

依据：[2023 交易规则 3.3.17、3.3.19](https://docs.static.szse.cn/www/lawrules/rule/trade/W020230217564423808793.pdf)、
[2026 交易规则](https://docs.static.szse.cn/www/lawrules/rule/trade/W020260424690713155663.pdf)。
当前 E0 采用收盘竞价开始前基准的展示契约有五个样本的独立逐笔对账支持；不能泛化为
其他阶段均采用同一固定范围，也不能套用历史“超范围存单”机制推断本次源订单无效。

## 6. 选帧审计与错误边界

- 不满足状态、前驱或时间条件的记录不生成比较任务，不维护停牌豁免、复牌撤销豁免。
  S0→H0→E0 没有正常参考；T0→E0 只比较有效 T0；H0→T0→C0→E0 比较盘中和收盘。
- 未选中的异常阶段不覆盖其他有效帧的结果，也不永久封锁后续正常转换。
- 按证券独立保存原始参考数量、状态计数、各阶段选中数量、未选中原因计数。
  原因使用 StatusNotApplicable、MissingNormalPredecessor、OutsideSelectionWindow、
  UnexpectedPhaseTransition、AdditionalStaticFrame；每条记录只计入一种选中或未选中类别。
- 正常不适用状态和额外静态帧只计数；其余三种原因各保存首个样例（毫秒时间、原始行号、
  前后状态）。不逐帧保存排除明细，不人为补三个阶段的审计伪帧。
- 原始参考数等于所有阶段选中数加未选中数；零原始参考与有原始参考但零有效帧分开报告。
- 参考时间回退、原始行号不递增、已选连续参考时间戳重复仍失败。文件、Schema、必要
  字段解析错误、恢复失败及已选参考的非法盘口仍失败，不因阶段筛选而放宽。
- SZ 日级涨跌停属性仍独立按现有全天契约检查，并用于收盘投影；未选中帧不解析盘口
  不等于取消日级属性检查。成交额精度或哨兵的已知变体仅按第 4 节的双空条件兼容，
  不由选帧规则豁免。
- 参考源只提供选择与比较依据，不补写订单簿。复牌恢复机制及待决限制见
  [实现说明](订单簿恢复实现说明.md)。

## 7. v2 结果分类与验收边界

新报告使用 report_schema_version=2，只为选中的真实参考帧生成以下四种结果：

| 分类 | 含义 |
| --- | --- |
| Matched | 同一候选状态或规定最终状态满足全部比较要求 |
| Mismatched | 存在合法参考及必要来源，但无法匹配 |
| DataError | 已选参考字段非法、必要比较元数据错误等 |
| MissingSource | 已选参考缺少必要恢复来源 |

未选中不是失败，也不是匹配，不产生 ExcludedByStatus 或虚拟 MissingSource。

```text
selected_references = matched + mismatched + data_errors + missing_source
comparable_references = matched + mismatched
match_rate = matched / comparable_references
```

分母为零时 match_rate=null。独立 selection_audit 与 coverage 按市场、品类、阶段报告
参考选中数量、覆盖证券数、无参考记录与无有效参考帧证券数。统计范围为显式请求、实际
参考及回放证券的并集，不推断未提供的全市场证券名录；跨日累计覆盖单位为证券日。

run_outcome=Passed 表示有选中参考且全部比较及必要检查通过；NoEligibleReferences 表示
零选中且运行无错误，两者退出码均为 0。必要检查或比较失败优先返回 Failed、非零退出码。
零比较不得显示 100%，也不得视为标准验收；部分覆盖的 Passed 必须同时展示覆盖情况。

历史报告保持原样，汇总工具按 v1/v2 分别读取、分别汇总，不能把旧虚拟锚点计数当作新
真实参考数。新 Rust 报告接口只接受 v2。字段说明见[使用手册](使用手册.md#报告怎么读)。

每次验收须记录版本、数据范围、策略和窗口；多次运行的合并统计不得冒充独立全量复跑。
跨日证据只支持已测范围，不能推断所有日期延迟上界或永远没有 15:00 后事件。
Snapshot 匹配证明规定的汇总盘口与成交统计一致，不单独证明订单身份、逐订单余量和
FIFO 正确；后者仍依赖逐订单对账及核心不变量测试。具体实验结论仅在本地 `reports/` 留存。
